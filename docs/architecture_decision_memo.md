# Architecture Decision Memo

**Which architecture would I ship—and why?** Ship the **Staged Two-Agent** architecture, with Single Agent retained as a lower-cost fallback.

**Evidence.** The current `evaluation/benchmark_results.json` contains 20 successful rows: both architectures passed all 10 shared edge cases, including missing information, catalog overlap, expired compliance, PII, prompt injection, budget overrun, and unavailable vendor-risk evidence. In the committed artifact, Single Agent averaged **1.39 ms**, **2 LLM calls**, and **1 tool call** per case. Staged averaged **0.65 ms**, **3 LLM calls**, and **1 tool call**. The artifact is explicitly marked `offline_stub`; these are local orchestration timings, not live provider latency. A live Groq run was attempted with the configured key but did not complete within the bounded run, so no unsupported live-performance claim is made.

**Decision rationale.** Staged separates evidence collection from decision review. The Analyst gathers budget, catalog, and vendor-risk evidence into a typed `StructuredEvidencePack`. The Reviewer receives that pack, applies deterministic policy rules, and formats the final `ProcurementOutput`. This boundary makes security escalations, approval thresholds, missing data, and conflicting vendor evidence easier to audit and test. It also limits the risk that one model turn both invents evidence and determines the recommendation.

**Tradeoff and guardrails.** Single Agent is simpler and uses one fewer model call, making it appropriate for low-risk requests or cost-sensitive fallback operation. Staged adds a handoff and reviewer call; it was faster in this small offline sample, but that result is not evidence of lower production latency. Its stronger separation of duties is the shipping rationale. Both paths use explicit Python `while` loops capped at 10 iterations, deterministic Pandas-backed tools, sanitized provider-neutral messages, Pydantic validation, JSON-mode final calls, and human review. Before production launch, repeat the benchmark against the configured provider with token cost, remote latency, retries, and live outage behavior recorded.
